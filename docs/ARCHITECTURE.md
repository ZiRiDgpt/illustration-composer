# Устройство решения

## Почему плагин Figma

В задании разрешён плагин. Исходная библиотека находится в Figma, поэтому её узлы можно использовать непосредственно, не конвертируя сложные группы, маски и обводки в стороннюю графическую модель. Сервис работает локально и не требует токенов или сервера.

## Хранение и извлечение объектов

В `src/plugin.js` каталог создаётся из страницы «Библиотека компонентов». Группы «Размер S» и «Размер L» определяют детализацию. Имена предметов сопоставляются с каноническими ключами. Маркер «Фоновые объекты» и вертикальные координаты разделяют состояния. Обход останавливается на целой группе найденного предмета: внутренние paths не регистрируются отдельными объектами.

Реальный исходник содержит безымянные Group для растения, папки, ручки и книг S. Их точные имена сопоставлены в `sourceHints`. У книг L маленькая белая деталь лежит отдельным соседним Vector; она присоединяется к записи через `sourceIds` по строгой проверке вложенных габаритов и малого размера. При клонировании эти части собираются внутри нейтрального контейнера. Исходная структура не меняется. Фактическая структура библиотеки закреплена в `tests/fixtures/source-inventory.json`; проверяются все 40 комбинаций.

В каталоге хранятся ID исходного узла, имя, ключ, размер, роль, габариты с учётом собственного преобразования и список цветов. При клонировании линейная часть исходного преобразования сохраняется, а сдвиг нормализуется внутри контейнера. Это предотвращает обрезку и смещение повёрнутых групп. SVG-превью экспортируются для интерфейса, но не сохраняются в данных документа. Каталог и палитры сохраняются в pluginData корня документа под ключом `composer-v1`. Повторный запуск проверяет существование исходных узлов. Ручной импорт заменяет запись с тем же ключом, размером и ролью.

Документ с библиотекой является источником истины. Новые композиции используют `clone()`, а не ссылки на растровую визуализацию. Внутри каждого объекта создаётся пустой frame-контейнер, который отделяет перемещение и поворот от структуры оригинальной иллюстрации. Контейнеры и композиции имеют метаданные в pluginData для дальнейших правок и экспорта.

## Подбор и компоновка

`src/core.js` не зависит от Figma и DOM. По свободной теме UI запрашивает локальную модель на localhost:4174. Сервер сравнивает embedding запроса с ассоциациями предметов; возвращённые ключи повторно проверяются в core, доступные варианты определяются каталогом S/L. Отдельный режим быстрых тем использует восемь словарей без модели. Предметный сценарий распознаёт имена и словоформы. Причина выбора передаётся пользователю, отсутствующие варианты и слабая связь дают ошибку. Подробнее — `SEMANTIC.md`.

Раскладка рассчитывает сетку для выбранного формата, оставляет отступы и при необходимости место слева под заголовок. Размер ячейки ограничивает **единый** коэффициент масштабирования всех предметов — в том числе фоновых. Предметы не приводятся к одинаковому размеру независимо друг от друга. Повороты и перемещения выполняются на обёртках. Обрезка фреймом допустима для фоновых объектов.

До шести главных объектов могут быть собраны автоматически. Новая вариация изменяет порядок размещения и смещение, создавая отдельный фрейм. Исходники остаются доступны для следующих композиций.

## Цвета

Поддерживается отдельная палитра для главных и фоновых объектов. Автоматическое извлечение распознаёт шесть колонок свотчей над разделом главных объектов: пары «фон / предметы» для трёх схем. Все три таблицы извлечены и проверены на настоящем исходнике. При другой разметке используется импорт JSON.

`buildPaletteMap` сопоставляет цвета по колонке и строке исходной таблицы. Базовой схемой служит «Сирень», в которой нарисована библиотека. Главные предметы используют цвета обеих колонок, фоновые — только `backgroundObjects`. Так сохраняются чёрный контур, белые участки и назначение цветных деталей. Для неизвестных дополнительных цветов есть резервное сопоставление по светлоте. Заливки, обводки и gradient stops получают новые цвета с сохранением прозрачности. Перед каждой перекраской внутреннее содержимое объекта повторно клонируется из исходника. Новые копии сначала готовятся во временном скрытом фрейме; при ошибке подготовки композиция остаётся прежней. Перекраска не изменяет геометрию оригинала. Отмена схемы возвращает исходный вариант с прозрачным фоном, сохраняя ID, позиции и порядок контейнеров объектов.

## UI и операции

Интерфейс получает каталог и превью SVG через `figma.ui.postMessage`. В `src/message-bridge.js` сообщения принимаются от непосредственного родителя или внешнего окна-предка: Figma использует несколько вложенных sandbox iframe. Сообщения от соседних окон и некорректные конверты отклоняются. Команды обработки документа последовательно выполняются в очереди. Кнопки, запускающие изменения, блокируются на время операции. Перетаскивание в превью переводит экранное смещение в координаты фрейма. Список слоёв показывает порядок от переднего к заднему.

Режим «Компактно» позволяет редактировать документ обычными средствами Figma. Кнопка обновления перечитывает композицию. Вызовы `figma.commitUndo()` отделяют операции для стандартной отмены.

Превью вписывается целиком в доступную область через ResizeObserver с сохранением пропорций. При выборе другой композиции или повторном запуске восстанавливаются запрос, размер, формат, расположение и схема из метаданных фрейма.

Во время перетаскивания обработчики mousemove/mouseup закреплены на окне iframe. Ответы с обновлённой сценой не пересоздают overlay в середине жеста. После завершения сдвиг переводится из экранных координат в координаты SVG. Исправление проверено по фактическим X/Y объекта в Figma.

## Экспорт

Результат экспортируется из настоящего фрейма через `exportAsync({ format: 'SVG_STRING', svgIdAttribute: true, svgSimplifyStroke: false })`. UI сохраняет полученную строку как `.svg`. Плагин не использует canvas, PNG или скриншоты для итоговой композиции. Импорт растровых узлов блокируется; итоговый SVG проверяется на `<image>` и встроенные растровые данные.

В Desktop обнаружена ошибка `SVG_STRING`: кириллица имён слоёв кодируется числовыми сущностями отдельных UTF-8 байтов. `repairSvgText` восстанавливает только корректные последовательности байтов с XML-экранированием; геометрия не меняется. Валидные Unicode-сущности и некорректные байты сохраняются. Исправленные имена проверены обратным импортом в Figma.

## Проверка и границы достоверности

Автоматические тесты проверяют смысловой и предметный подбор, отсутствие подстановок для неизвестных запросов, общие пропорции, три формата и раскладки, регистрацию главных/фоновых вариантов, клонирование без изменения оригиналов, операции редактирования, сохранение каталога и повторную перекраску. Адаптерные тесты используют заменитель Figma API и не подтверждают поведение настоящего рендерера Figma.

В настоящем Figma Desktop проверены 40 вариантов каталога, схемы, оба сценария, свободные метафоры, перетаскивание, копирование/поворот/удаление, порядок слоёв, смена роли, импорт JSON-палитры и экспорт. Проходят 21 автоматический тест и отдельные проверки настоящей модели. Результаты и границы покрытия — в `RUNTIME-CHECK.md`.

## AI-инструменты

Для разработки кода, интерфейса и тестов использован Codex. В продукте свободную тему обрабатывает локальная multilingual MiniLM через Transformers.js; внешнего AI API нет, ключи не нужны. Новые изображения с помощью AI не создавались. Восемь быстрых тем — дополнительный режим правил без модели.

# Сборка — конструктор иллюстраций

Плагин Figma для тестового задания: автоматически собирает композиции из исходных векторных предметов. Подбор по свободной теме выполняет локальная модель; API-ключ и платный сервис не нужны. По списку предметов и восьми быстрым темам плагин работает самостоятельно.

**Версия 0.3.0.** Проверено в настоящем Figma Desktop: 40 вариантов, три исходные схемы, загрузка палитры JSON, оба сценария сборки, перетаскивание, поворот, копирование/удаление, порядок слоёв, смена роли и SVG-экспорт. Проходят 21 автоматический тест и отдельные проверки настоящей модели на шести новых формулировках. Общий файл задания не изменялся.

[Рабочая копия Figma с примером](https://www.figma.com/design/5JCRrjhDFq0q4h5vC7o7TZ/?node-id=5001-2) открыта для просмотра по ссылке; гостевой просмотр проверен. [Исходники GitHub](https://github.com/ZiRiDgpt/illustration-composer). [Сверка с каждым пунктом ТЗ](docs/REQUIREMENTS.md), [фактические проверки](docs/RUNTIME-CHECK.md).

## Запуск за несколько минут

1. Откройте Figma Desktop и войдите в свой аккаунт.
2. Откройте [файл задания](https://www.figma.com/design/4MCFttsSoP7hgQh29zq5G3/). Создайте редактируемую копию в своих черновиках. Если копирование запрещено владельцем, запросите копию с библиотекой компонентов.
3. В меню Figma выберите **Plugins → Development → Import plugin from manifest…** и укажите `manifest.json` из корня проекта. Готовая сборка лежит в `dist/`. Для предметного режима и быстрых тем установка npm-пакетов не требуется.
4. Запустите **Plugins → Development → Сборка — конструктор иллюстраций**.
5. Нажмите **Подключить библиотеку Figma**. Плагин найдёт страницу «Библиотека компонентов» и группы «Размер S» / «Размер L». Имена объектов и расположение раздела «Фоновые объекты» используются для каталогизации.
6. Выберите S/L. Для первого запуска без модели переключитесь на **По объектам**, введите «Книга, лампа, ручка» и нажмите **Собрать**. Для свободной метафоры запустите локальный модуль по инструкции ниже; для готовых тем выберите **Быстрые темы**.
7. Выберите объект в превью или списке слоёв: его можно перетащить, повернуть, скопировать, удалить или переместить по слоям. Нажмите **Компактно**, если хотите редактировать копии обычными инструментами Figma. **Обновить из Figma** перечитает результат.
8. Нажмите **Скачать SVG**. Это настоящий экспорт созданного фрейма через Figma API, с векторными группами, масками и именами слоёв.

`illustration-composer-local` — локальный идентификатор разработки. Если Figma требует зарегистрированный ID или вы хотите опубликовать плагин, создайте новый плагин через **Development → New plugin**, затем замените только `id` в нашем `manifest.json` на выданный Figma ID. Остальные поля сохраните.

## Свободная тема или метафора

Установите Node.js 20+ и выполните в папке проекта:

```powershell
npm.cmd ci
npm.cmd run semantic
```

Дождитесь сообщения **Смысловой подбор готов**. В плагине выберите **По теме → Свободная тема** и введите, например, «Начать новую главу в жизни» или «Дать идее прорасти». При первом запуске скачиваются около 135 МБ модели; следующие запросы обрабатываются локально. Figma обращается только к localhost:4174, запросы и иллюстрации внешнему AI-сервису не отправляются. Подробности и границы метода — в [SEMANTIC.md](docs/SEMANTIC.md).

## Что реализовано

- Автоимпорт оригинальных объектов: книга, телефон, наушники, лампа, кошелёк, монета, папка, ручка, пазл, растение. Поддерживаются распространённые русские и английские имена.
- Ручной импорт выделенного вектора с назначением названия, размера S/L и состояния «главный» / «фоновый». Позволяет исправить каталог, если структура исходного файла отличается.
- Два сценария: названия предметов и свободный текст с локальной моделью смыслового поиска. Восемь быстрых тем доступны дополнительно без модели. Слабое смысловое соответствие возвращает предложение уточнить запрос.
- Три расположения: собранно, со смещением, с местом под заголовок. Форматы 1200×630, 1080×1080, 1080×1440 и собственный размер от 240 до 4096 пикселей.
- Все объекты автоматически масштабируются одним коэффициентом. Их взаимные пропорции сохраняются; размер S не смешивается с L.
- Добавление объектов из библиотеки, перемещение, поворот на 15°, дублирование, удаление, порядок слоёв, смена главного/фонового варианта при наличии пары.
- Извлечение трёх палитр из таблиц исходника при распознанной геометрии; импорт пользовательской палитры из JSON. Фоновые объекты перекрашиваются только в цвета своей части палитры.
- Перекраска solid-заливок, обводок и gradient stops; прозрачность сохраняется. Каждая перекраска начинается с исходного объекта, чтобы не накапливать потери цветов.
- Библиотека и палитры сохраняются в данных документа и доступны при повторном запуске.
- Экспорт SVG с сохранением векторов и проверкой отсутствия растровых изображений.

## Как подключить объект вручную

Если автоимпорт не нашёл объект, нажмите **Компактно**, выделите всю векторную группу предмета в исходной библиотеке, раскройте **Импорт выделенного объекта**, выберите имя, S/L и роль, затем нажмите **Добавить выделенное**. Для автоматического определения имени можно выделить несколько объектов сразу. Для назначения конкретного имени — только один.

Добавлять нужно исходный предмет целиком, а не отдельные paths и не фрейм со всей библиотекой. Растровые картинки и текст в объекте отклоняются. Исходный файл не переписывается: создаются независимые копии в новом фрейме композиции.

## Палитра JSON

Формат файла:

```json
{
  "name": "Моя схема",
  "background": "#DCD3F7",
  "objects": ["#191919", "#A38ADB", "#F7E8A5", "#FFFFFF"],
  "backgroundObjects": ["#A38ADB", "#C4B4EC", "#DCD3F7"]
}
```

Цвета выше иллюстрируют формат; для сдачи используйте точные значения палитры из исходного файла. `objects` — разрешённые цвета главных предметов, `backgroundObjects` — отдельная шкала для фоновых. Цвет `background` может встречаться в предметах. Палитра загружается через **Цветовая схема → Загрузить**, затем применяется кнопкой **Применить к композиции**.

Исходные цвета без палитры сохраняются с прозрачным фоном. Для трёх схем задания используется соответствие ячеек исходной таблицы: чёрные контуры и белые детали сохраняются, цветные детали переходят в соответствующие цвета новой схемы. Главные предметы используют обе колонки таблицы, фоновые — только фоновую. Для дополнительных цветов пользовательских объектов применяется сопоставление по светлоте.

## Сборка и проверки для разработчика

Нужен Node.js 20+. Базовые проверки и сборка не требуют установки внешних пакетов; локальный смысловой модуль устанавливается через `npm.cmd ci`.

```powershell
npm.cmd run check
npm.cmd test
npm.cmd run build
```

При запущенном смысловом модуле: `npm.cmd run test:semantic`. Проверка сохранённых SVG: `python scripts/verify-examples.py` (Python 3, стандартная библиотека).

Для просмотра интерфейса без Figma:

```powershell
npm.cmd run preview
```

Откройте `http://127.0.0.1:4173`. В этом режиме показан только интерфейс: библиотека, работа с документом и SVG-экспорт требуют Figma. Превью не содержит подменяющих исходник иллюстраций.

## Состав проекта

- `src/core.js` — распознавание названий и тем, планирование композиций, палитры.
- `src/plugin.js` — чтение библиотеки, клонирование и редактирование узлов, экспорт, сохранение каталога.
- `src/ui.html`, `src/ui.js`, `src/style.css` — интерфейс и обмен сообщениями с плагином.
- `scripts/build.mjs` — сборка двух самодостаточных файлов в `dist/`.
- `tests/` — проверки алгоритмов и сценариев Figma API на тестовом адаптере. Тестовые узлы не включаются в плагин.
- `docs/ARCHITECTURE.md` — описание устройства для сдачи.
- `docs/ACCEPTANCE.md` — сценарии проверки на реальном файле.
- `examples/recipes.json` — точные параметры трёх сохранённых композиций.
- `examples/01-study.svg`, `02-finance.svg`, `03-connection.svg` — результаты настоящего экспорта Figma, с исправленной кодировкой имён слоёв.
- `server/` — локальная модель, смысловые ассоциации и HTTP-модуль.
- `demo/demo.mp4` — запись реальных действий в Figma: оба сценария, палитра, правки и экспорт; без звука.
- `docs/HANDOFF.md` — состав сдачи и текст сопровождения.

## Ограничения первой версии

Смысловой поиск ограничен образами десяти имеющихся предметов и может ошибаться; это не генеративная LLM и не обещание понимания любой метафоры. Новые рисунки не создаются. В объяснении показаны выбранные ассоциации, результат можно отредактировать. Новый вариант создаётся отдельным фреймом. Изменение формата или S/L применяется при следующей сборке.

Автоимпорт зависит от структуры библиотеки. Для безымянных групп именно этого задания предусмотрен проверенный профиль имён; для другой библиотеки доступен ручной импорт. Если таблица цветов не распознана, нужна палитра JSON. Не предусмотрена автоматическая перекраска эффектов и нестандартных paint-типов. Вручную добавленные в Figma элементы вне зарегистрированных объектов не входят в список слоёв плагина; растровые элементы блокируют итоговый экспорт.
